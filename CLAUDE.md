# geminpy — developer guide

`geminpy` is a macOS-only Python CLI and library that automates Google's OAuth
flow for the `gemini` CLI. It flips the default browser to Chrome for Testing,
launches `gemini`, drives the sign-in screens over the Chrome DevTools Protocol
with Playwright, extracts the clean response, and restores the browser.

The old `work/gemini_wrapper.py` prototype has been fully ported into
`src/geminpy/`. There is no `work/` directory any more.

## Commands

```bash
hatch run test:test        # run the mocked test suite
hatch run test:test-cov    # tests with coverage
hatch run lint:style       # ruff check + format
hatch run lint:typing      # mypy
hatch run lint:fix         # ruff --fix + format
hatch build                # wheel + sdist (version from git tag via hatch-vcs)
```

All tests mock every browser and network interaction — no live Gemini account and
no real Chrome are needed. Keep it that way; live-only paths (interactive mode,
real OAuth) are integration concerns, not CI.

## Layout

```
src/geminpy/
├── api.py            # public: ask, ask_async, call_gemini_cli
├── cli.py            # Fire CLI entry point
├── browser/
│   ├── automation.py # OAuthAutomator (Playwright state machine), UserResolver
│   ├── chrome.py     # ChromeManager, ChromeTestingManager
│   └── manager.py    # BrowserManager (macdefaultbrowsy; darwin-guarded import)
├── core/
│   ├── config.py     # AppConfig / ChromeConfig / GeminiConfig dataclasses
│   ├── constants.py  # URLs, rate-limit indicators, success pattern
│   ├── exceptions.py # GeminiError and subclasses
│   └── models.py     # pro/flash alias resolution from installed gemini-cli
└── gemini/
    ├── client.py     # GeminiClient — orchestrates the four phases
    ├── executor.py   # GeminiExecutor — subprocess lifecycle
    └── parser.py     # ResponseParser — strips auth noise from stdout
```

## Conventions

- Use `uv pip`, never bare `pip`. Run modules with `python -m`.
- Type hints in simplest form (`list`, `dict`, `str | None`). f-strings. `pathlib`.
- Loguru for logging; `--verbose` toggles debug output.
- Fire + Rich for the CLI.
- Keep a `this_file:` marker near the top of each source file.
- `src/geminpy/__version__.py` is generated by hatch-vcs and git-ignored — never
  edit or commit it.

## Release

Tag `vX.Y.Z` (or run `uvx gitnextver@latest`). The `release.yml` workflow builds
the distributions, creates a GitHub release, and publishes to PyPI via trusted
publishing. `hatch-vcs` derives the version from the tag, so the working tree must
be clean and the tag must be on `main`.
